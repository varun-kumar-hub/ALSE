# Simulation — The Learner Simulator and the Anti-Circularity Guarantee

This is the document a sharp judge will implicitly test you on, whether or not they name it. Read
§1 twice.

---

## 1. The circularity problem, stated plainly

The obvious way to evaluate an adaptive tutor is to build a simulated learner and show your agent
teaches it well. The obvious way to build a simulated learner is to use the same learning model your
agent uses. **If you do that, your experiment proves nothing** — you have built a universe whose
physics were chosen to make your policy correct, and then reported that your policy is correct.

Almost every adaptive-learning demo has this flaw. Most do not know it. LOOM forecloses it with four
independent barriers, in increasing order of strength:

| # | Barrier | Strength |
|---|---|---|
| B1 | **Different model families.** The simulator's generative process and the agent's estimator are structurally different — neither is a special case of the other. | Design |
| B2 | **Different parameters.** Even where forms are analogous, the simulator's parameters are drawn per learner from distributions the agent never sees and cannot recover exactly. | Design |
| B3 | **A code import boundary.** `loom/sim/` may not import `loom/agent/` or `loom/ml/`, and vice versa. Enforced by an AST test in CI. | Mechanical |
| B4 | **A database permission boundary.** Ground truth lives in schema `sim`. The application role `loom_app` has no `USAGE` grant on it. Application code attempting to read it gets a Postgres permission error. | Enforced by the DBMS |

**The demo move:** open a psql session as `loom_app`, run `SELECT * FROM sim.learner_truth LIMIT 1;`,
and show the permission denied error on screen. It takes eight seconds and it ends the question.

## 2. The simulator's generative model

The simulator is a **continuous-latent, compensatory, misconception-conditioned response process with
Ebbinghaus forgetting and engagement dynamics.** The agent's estimator (M1) is **discrete-state
Bayesian Knowledge Tracing with graph credit propagation**. These are different families.

### 2.1 Latent state of a simulated learner

```python
@dataclass
class TrueLearnerState:
    theta: dict[ConceptId, float]        # true ability per concept, continuous, unbounded-ish
    learn_rate: dict[ConceptId, float]   # how much theta moves per effective intervention
    forget_rate: float                   # per-learner Ebbinghaus lambda
    transfer: float                      # how much learning on c raises related concepts
    misconceptions: dict[MiscId, float]  # activation strength in [0, 1], NOT a probability
    slip: float                          # per-learner careless-error rate
    guess_skill: float                   # ability to eliminate distractors when unsure
    engagement: float                    # [0, 1], evolves
    fatigue_rate: float
    hint_reliance: float                 # propensity to request hints instead of thinking
    reading_speed: float                 # drives response time
```

### 2.2 The response process

Given item `i` on concept `c`:

**Step 1 — effective ability.** Compensatory across the item's concepts, weighted by the prerequisite
`tau` structure, and *penalised by any active misconception attached to this item*:

```
theta_eff = w_primary * theta[c]
          + (1 - w_primary) * mean( theta[c2] for c2 in secondary_concepts )
          - sum_over_m_relevant( misconceptions[m] * interference[m][i] )
```

`interference[m][i]` is non-zero only when item `i` has a distractor generated by misconception `m`.
This is the key structural difference from the agent's model: **misconceptions actively subtract
ability on the specific items they corrupt**, rather than being a separate belief tracked alongside
mastery.

**Step 2 — response probability.** A 3PL-style curve with per-learner slip and guess, plus a hint
boost:

```
p_raw     = 1 / (1 + exp(-a_i_true * (theta_eff - b_i_true)))
p_guess   = 0.25 + 0.15 * guess_skill          # 4-option items
p         = p_guess + (1 - p_guess - slip) * p_raw + hint_boost(hints_used)
correct   ~ Bernoulli(p * engagement_multiplier)
```

Note `a_i_true` and `b_i_true` are the **simulator's** item parameters, drawn once per experiment as
`authored_prior + N(0, 0.25)`. The agent's M4 must *estimate* these from data and will not recover
them exactly. That gap is real, measured, and reported.

**Step 3 — which wrong option.** This is where misconceptions become observable:

```
if not correct:
    active = [m for m in misconceptions if strength[m] > 0.3 and m has a distractor on item i]
    if active and rng.random() < max(strength[active]):
        choose the distractor generated by argmax_strength(active)     # systematic error
    else:
        choose uniformly among wrong options                            # careless error
```

A learner with a strong misconception produces a **consistent** wrong-answer signature. A careless
learner produces noise. M3's whole job is to tell those apart, and this is the process that makes the
distinction real rather than assumed.

**Step 4 — response time.** Log-normal, driven by item difficulty gap, reading speed, engagement, and
whether the learner is gaming:

```
log_rt ~ Normal( mu_base + 0.45*|b_i - theta_eff| - 0.6*engagement - 1.4*is_gaming,  sigma )
```

The `-1.4 * is_gaming` term is what makes near-instant clicking detectable by M7.

### 2.3 Effect of teaching actions on the true state

| Agent action | True effect in the simulator |
|---|---|
| `TEACH(c)` | `theta[c] += learn_rate[c] * readiness(c) * engagement`, where `readiness(c)` is the mean prerequisite `theta` normalised — **teaching an unready learner genuinely does little**, which is the ground truth that makes the readiness gate valuable. Transfer: `theta[c2] += transfer * 0.3 * gain` for graph neighbours. |
| `REVISE(c)` | `theta[c] += 0.6 * learn_rate[c]`, no readiness scaling, and resets the forgetting clock for `c`. |
| `ASSESS(i)` | Testing effect: `theta[c] += 0.12 * learn_rate[c]` if correct, `0.05` if incorrect. Retrieval practice genuinely teaches, and modelling that is what makes `ASSESS` more than measurement. |
| `HINT(l)` | Raises `hint_boost` on the open item; `+0.03 * learn_rate` learning, i.e. much weaker than solving unaided. Also `hint_reliance += 0.05` — hint-giving creates hint-dependence. |
| `EXPLAIN(m)` | `strength[m] *= (1 - remediation_strength[m])` from the table in [`Concept_Graph.md`](./Concept_Graph.md) §3, and `+0.1 * learn_rate` on concepts where `m` is primary. |
| `EASIER`/`HARDER` | As `ASSESS`, plus an engagement effect: a well-matched difficulty raises engagement, a badly matched one lowers it. |
| `BRANCH(b)` | `engagement += 0.15`, capped at 1.0. Novelty genuinely helps, briefly. |
| `CONSOLIDATE(c)` | Resets the forgetting clock for `c` and *reduces* `forget_rate` slightly for that concept — spaced retrieval strengthens retention. |

### 2.4 Between-step dynamics

```
# Forgetting, per concept, on every step
theta[c] = floor[c] + (theta[c] - floor[c]) * exp(-forget_rate * steps_since_seen[c])

# Engagement decay and recovery
engagement -= fatigue_rate
engagement += 0.08 if last response was correct and well-matched
engagement = clip(engagement, 0.1, 1.0)

# Gaming onset
is_gaming = engagement < 0.35 and rng.random() < hint_reliance

# Incidental misconception decay
for m: strength[m] *= (1 - incidental_decay[m]) if answered correctly on an item where m applies
```

## 3. The seven learner profiles

Profiles are **parameter distributions**, not scripts. Each simulated learner samples its own
parameters from its profile's distribution, so no two learners in a cohort are identical.

| ID | Name | Defining parameters | What it tests |
|---|---|---|---|
| **P1** | **Sprinter** — fast and accurate | High `theta` prior (0.55 ± 0.15), high `learn_rate`, low `slip`, fast `reading_speed` | Does the agent avoid wasting budget teaching what is known? Does it escalate difficulty? |
| **P2** | **Deliberator** — slow and accurate | Mid `theta`, low `slip`, slow `reading_speed` (2.5x), high engagement stability | Does the agent avoid mistaking slowness for struggle? Direct test of M7's discriminative power. |
| **P3** | **Guesser** — fast and careless | Mid `theta`, high `slip` (0.28), high `guess_skill`, very fast `reading_speed` | Can M1 avoid over-crediting lucky guesses, and can M3 avoid inventing misconceptions from noise? |
| **P4** | **Anchored** — one deep misconception | Normal parameters, but one misconception (sampled from M3, M6, or M8) at strength 0.85 with low `incidental_decay` | The headline test. Does the agent detect it, name it, remediate it, and verify the fix — rather than drilling forever? |
| **P5** | **Cracked Foundation** — prerequisite gap | High `theta` on C5–C10, near-zero on C3 and C4 | Does the agent walk *backwards* down the graph? This is trigger T3's test and the single most visually compelling behaviour in the demo. |
| **P6** | **Leaky Bucket** — learns fast, forgets fast | High `learn_rate` (0.45), high `forget_rate` (0.28) | Does the agent discover that `CONSOLIDATE` is worth its cost? A fixed sequence cannot possibly handle this learner. |
| **P7** | **Fader** — engagement collapses | Normal start, high `fatigue_rate` (0.09), high `hint_reliance` (0.6) | Does M7 fire in time, and does the agent respond with `BRANCH`/`EASIER` instead of more hints? |

**Cohort composition.** Evaluation cohorts are stratified: 100 learners of each profile plus 200
drawn from a blended distribution, giving N = 900 per seed. Reported per profile *and* in aggregate,
because the aggregate hides the most interesting story.

## 4. Cohort generation

```
generate_cohort(profile_mix, n, seed) -> list[TrueLearnerState]
    rng = np.random.default_rng(seed)
    for k in 1..n:
        profile = sample(profile_mix, rng)
        state   = sample_parameters(profile, rng)
        inject_misconceptions(state, profile, rng)
        persist to sim.learner_truth with (cohort_id, learner_index, seed)
```

**Seed discipline** ([`Contract.md`](./Contract.md) C6.6):

| Cohort | Seed range | Used for |
|---|---|---|
| Pretraining | 1000–1999 | Training M1–M8, fitting IRT, tuning `alpha..delta` |
| Development | 5000–5099 | Day-to-day debugging while building |
| **Evaluation** | 9000–9999 | **Every reported number.** Never touched until Hour 30. |

No learner appears in two ranges. The evaluation cohort is not looked at during development. If a
result on the evaluation cohort is disappointing, we report it — we do not go back and re-tune. That
discipline is the difference between an experiment and a demo.

## 5. What crosses the boundary

**The complete set of information the agent receives per step:**

```python
Observation(
    item_id:          str,
    chosen_option_id: str,
    is_correct:       bool,
    response_time_ms: int,
    hints_used:       int,
    step:             int,
)
```

Six fields. Nothing else. No `theta`, no misconception strengths, no profile label, no `learn_rate`.
The `Observation` type is defined in `loom/domain/observation.py` and is the *only* type that both
`loom/sim/` and `loom/agent/` import — which is exactly why the import-boundary test permits
`loom/domain/` and forbids everything else.

**What the evaluation harness may join** (role `loom_eval`, after a run completes only):

| Join | Purpose |
|---|---|
| `app.mastery_estimates` × `sim.learner_truth_trajectory` | Calibration: estimated vs true mastery |
| `app.misconception_beliefs` × `sim.learner_misconceptions` | Misconception detection precision/recall |
| `app.run_metrics` × `sim.learner_truth` | Headline outcome by profile |

Doing these joins *during* a run is forbidden ([`Contract.md`](./Contract.md) C4.5) and would be
visible in the code review a judge might ask for.

## 6. Validating the simulator itself

A simulator that produces implausible learners invalidates everything downstream. Four checks, run at
Hour 12 and again before the headline experiment:

| # | Check | Pass criterion |
|---|---|---|
| V1 | **Overall accuracy is plausible** | Cohort mean accuracy on the fixed-sequence baseline falls in 0.45–0.70. Outside that band the item bank is mis-calibrated. |
| V2 | **Learning is possible but not trivial** | Under B0 (fixed sequence), mean weighted mastery gain is positive and in 0.15–0.35. If B0 gains nothing, nothing can be learned; if B0 gains everything, adaptivity cannot matter. **This check protects the headline result from both directions.** |
| V3 | **Profiles are distinguishable** | A simple classifier on observable features separates the 7 profiles above chance by a clear margin, but not perfectly (accuracy 0.4–0.75). Perfect separability would mean the profiles are caricatures. |
| V4 | **Misconceptions are detectable but not obvious** | Injected misconceptions produce a distractor-consistency signal that is above noise, but a naive "one wrong answer = misconception" rule scores below 0.45 F1. Otherwise M3 is solving a trivial problem. |

**V2 is the honesty check that matters most.** It is entirely possible to accidentally build a
simulator where the fixed baseline is crippled — for instance, if `TEACH` had no readiness scaling and
the baseline taught C10 to a learner with no C3. We would then "beat the baseline" by a huge margin
and the result would be meaningless. V2 catches exactly that, and we state on the dashboard that it
passed and what its value was.

## 7. Known limitations we will state out loud

A judge who asks "how do you know this transfers to real students?" should get this answer, not a
defensive one:

1. **It does not, and we do not claim it does.** Every result in this project is a statement about
   simulated learning gain under a stated generative model. We say "simulated" on every chart axis.
2. **The simulator embeds pedagogical assumptions** — that retrieval practice teaches, that hints
   create dependence, that spaced review reduces forgetting. These are drawn from the education
   literature, but they are assumptions, and if they are wrong the ranking of actions could change.
3. **Misconceptions are modelled as independent.** Real ones co-occur and cause one another.
4. **Engagement is a scalar.** Real motivation is not.
5. **The item bank is 28 items.** Real IRT calibration uses hundreds.

What the simulation *does* establish is the thing that is actually in question: **given a learner
model, does budget-aware planning with misconception diagnosis beat a fixed sequence and a
threshold heuristic?** That question is answerable here, and we answer it with confidence intervals.

Saying this clearly is not a weakness in the presentation. It is the strongest possible signal that
you understand what you built.
