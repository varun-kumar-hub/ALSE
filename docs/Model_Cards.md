# Model Cards — The Eight Intelligence Components

Six required by PS 6, two bonus. Every component here satisfies
[`Contract.md`](./Contract.md) C2.2 (independently evaluable output with a held-out metric) and C2.3
(materially changes agent behaviour, proven by ablation).

**Quick index**

| ID | Name | Family | Required? | Feeds |
|---|---|---|---|---|
| M1 | Knowledge-State Estimator (KSE) | Bayesian Knowledge Tracing + graph credit propagation | Required | Everything |
| M2 | Concept-Mastery Predictor (CMP) | Gradient-boosted trees | Required | Risk, projection, readiness |
| M3 | Misconception Detector (MCD) | Multinomial classifier + Bayesian belief update | Required | `EXPLAIN`, trigger T1 |
| M4 | Difficulty Estimator (DEM) | 2PL IRT, EM-fitted, online recalibration | Required | `EASIER`/`HARDER`, risk |
| M5 | Learning-Gain Predictor (LGP) | Gradient-boosted regressor | Required | `Gain(a)` |
| M6 | Action/Branch Ranker (ABR) | Pairwise LambdaRank | Required | Tie-break, disagreement diagnostic |
| M7 | Engagement & Gaming Detector (EGD) | Sequence-feature classifier | **Bonus** | Risk, trigger T5 |
| M8 | Learner Archetype Classifier (LAC) | Gaussian mixture + posterior | **Bonus** | Cold-start priors |

Training data for all eight: transcripts generated by the simulator on **pretraining seeds
1000–1999** (4,000 learners, ~85,000 interactions). Labels are derived from **observable outcomes
only** — never from simulator latent parameters ([`Contract.md`](./Contract.md) C4.7). Evaluation is
on a held-out slice of pretraining seeds; the *policy* is evaluated separately on seeds 9000–9999.

## M1 — Knowledge-State Estimator (KSE)

**Question it answers:** given everything observed so far, what is the probability the learner has
mastered each of the 10 concepts, and how sure are we?

**Family.** Bayesian Knowledge Tracing per concept, extended three ways: (a) a Beta belief instead of
a point estimate, so we carry variance; (b) **graph credit propagation** — evidence on a concept
partially updates its prerequisites via the `tau` weights in
[`Concept_Graph.md`](./Concept_Graph.md) §2; (c) an explicit forgetting term.

**Parameters per concept**, fitted by EM on the pretraining transcripts:
`p_init` (prior mastery), `p_learn` (transition), `p_slip`, `p_guess`, `lambda_forget`.

**Update on an observation** `(item i on concept c, correct)`:
```
# 1. Evidence likelihood, hint-discounted
p_slip_eff  = p_slip_c  + 0.10 * hints_used
L_correct   = m * (1 - p_slip_eff) + (1 - m) * p_guess_c
posterior_m = m * (1 - p_slip_eff) / L_correct            # if correct
            = m * p_slip_eff / (1 - L_correct)            # if incorrect

# 2. Learning transition
m' = posterior_m + (1 - posterior_m) * p_learn_c

# 3. Graph credit propagation to prerequisites p of c
for p in parents(c):
    m_p' = m_p + tau[p][c] * rho * (m' - m_p)             # rho = 0.35

# 4. Variance update: Beta pseudo-counts
n_c += 1;  var_c = m'(1-m') / (n_c + 1)
```

**Inputs:** interaction stream. **Output:** `{concept: Belief(mean, var, n)}`.

**Independently evaluable metric.** Next-item correctness prediction on held-out transcripts.

| Metric | Target | Compare against |
|---|---|---|
| AUC (next-response correctness) | ≥ 0.78 | Majority-class baseline 0.50; per-concept mean rate 0.62 |
| MAE vs ground-truth mastery | ≤ 0.12 | Cannot be beaten by construction — this is the honesty number |
| Expected Calibration Error | ≤ 0.08 | |

**Known failure modes.**
- Cold start: with fewer than 2 observations on a concept, the estimate is essentially the prior. This
  is precisely why M8 (archetype priors) exists as a bonus component.
- Graph propagation can over-credit: a lucky guess on C8 nudges C3 upward. `rho = 0.35` damps this;
  the residual is visible in the calibration plot and we do not hide it.
- Forgetting is modelled per concept with a single `lambda`, while the simulator gives each *learner*
  a forget rate. The agent systematically under-estimates decay for the "Leaky Bucket" profile. **We
  show this**: it is a genuine, interesting, honest limitation.

**Ablation impact (expected).** Removing M1 removes the system. Not ablatable; instead we ablate the
graph propagation term, which we expect to be worth ~4–7% of headline gain.

## M2 — Concept-Mastery Predictor (CMP)

**Question it answers:** what is the probability this learner answers correctly on a concept they have
**never been assessed on**?

M1 tells you about concepts you have evidence for. M2 generalises *across* the graph to concepts you
do not. This is what makes the readiness gate and the mastery projection possible.

**Family.** `XGBClassifier` (fallback: `HistGradientBoostingClassifier`), ~180 trees, depth 4.

**Features (24):**

| Group | Features |
|---|---|
| Target concept | depth in DAG, curriculum weight `w_c`, mean authored difficulty, n prerequisites |
| Prerequisite evidence | min / mean / max prerequisite mastery, weighted-by-`tau` prerequisite mastery, n prerequisites with evidence |
| Global learner | overall weighted mastery, `theta`, mean response-time z-score, total items attempted, overall accuracy |
| Error structure | total errors, errors on prerequisites, max misconception posterior, n misconceptions above 0.4 |
| Trajectory | steps elapsed, hints per item, accuracy over last 5, accuracy trend (slope over last 8) |

**Output:** `P(correct | learner, unseen concept)`, plus a projected mastery for that concept.

**Metric.** Held-out AUC on genuinely unattempted concepts.

| Metric | Target | Baseline |
|---|---|---|
| AUC | ≥ 0.74 | Global mean rate 0.50; "use nearest prerequisite mastery" heuristic ~0.66 |
| Brier | ≤ 0.20 | |

**Where it is used.** The `TEACH` readiness gate, `r_frustration` in the risk term, and the Predicted
Final Mastery panel.

**Failure modes.** Degrades for C10 (word problems), where transfer from prerequisites is weakest and
the reversal misconception dominates — exactly where a human teacher would also struggle to predict.
Reported per concept, not just in aggregate.

## M3 — Misconception Detector (MCD)

**Question it answers:** which specific faulty rule is this learner applying?

This is the component that makes LOOM feel intelligent, and the one judges will probe.

**Family.** Two stages.
1. **Per-response classifier** — multinomial logistic regression over response features → a
   distribution over `{M1..M8, none}`. Trained on pretraining transcripts where the label is the
   misconception attached to the chosen distractor.
2. **Bayesian belief accumulator** — a per-misconception posterior updated sequentially, so a single
   distractor match is suggestive but three across different items is near-certain:
```
logit(P(m))  <-  logit(P(m)) + w_evidence * (classifier_score_m - prior_m) - decay_m
```
with `decay_m` applied when a learner answers correctly on an item where `m` would have produced a
distractor — negative evidence, which most systems ignore.

**Features (17):** chosen option's misconception tag, whether the chosen distractor is unique to one
misconception or ambiguous across several, item concept, item difficulty, response-time z-score,
hints used, whether the same misconception's signature appeared in the previous 3 responses, streak
of errors on the concept, and the *consistency* of the error pattern across the session.

**Output:** `{misconception_id: posterior}` for all 8, every step.

**Metrics.**

| Metric | Target | Note |
|---|---|---|
| Macro-F1 (per-response, 9 classes) | ≥ 0.70 | Random 0.11; majority ("none") 0.31 |
| Session-level detection rate of the *injected* misconception | ≥ 0.85 within 5 responses | Ground truth from `sim`, evaluated offline only |
| False-positive rate (asserting a misconception the learner does not hold) | ≤ 0.12 | Costly: it wastes an `EXPLAIN` |
| Median responses to confident detection (P > 0.65) | ≤ 3 | |

**Failure modes.**
- **M8 (reversal) is thin** — only 3 items can detect it ([`Concept_Graph.md`](./Concept_Graph.md)
  §4.3), so its per-class F1 will be the lowest. Stated openly in the confusion matrix on the
  dashboard.
- **Ambiguous distractors**: some wrong answers are reachable by two different faulty rules (M2 and M4
  can coincide on one-step equations). The classifier splits probability; the accumulator resolves it
  over time. This is why the two-stage design exists and is worth explaining on stage.
- A guessing learner (profile P3) generates distractor matches that mean nothing. The response-time
  feature and M7's `gaming_prob` are what keep this in check.

## M4 — Difficulty Estimator (DEM)

**Question it answers:** how hard is each item really, and where is this learner's ability?

**Family.** Two-parameter logistic IRT.
```
P(correct | theta, a_i, b_i) = 1 / (1 + exp(-a_i * (theta - b_i)))
```
- **Offline:** joint EM over the pretraining transcripts estimates `(a_i, b_i)` for all 28 items,
  regularised toward the authored priors in [`Concept_Graph.md`](./Concept_Graph.md) §4 (a `N(prior,
  0.5)` penalty). With 28 items and 85k responses this is well-identified.
- **Online:** the learner's `theta` is updated every response by a single Newton step on the item
  likelihood — cheap, stable, and the reason the difficulty progression chart moves smoothly.

**Output:** `(a_i, b_i)` per item with standard errors; live `theta` with standard error.

**Metrics.**

| Metric | Target |
|---|---|
| Correlation of estimated `b` with authored prior | ≥ 0.80 (validates that the authored bank is coherent) |
| Item-fit infit MSQ within [0.7, 1.3] | ≥ 24 of 28 items |
| `theta` recovery correlation vs simulator ground-truth ability | ≥ 0.85 (offline evaluation only) |
| Response-prediction AUC | ≥ 0.76 |

**Where it is used.** `EASIER`/`HARDER` band selection, `P(correct|a)` for the risk term, and the
Difficulty Progression panel (which plots item `b` against learner `theta` over time — one of the
most legible charts in the dashboard).

**Failure modes.** Items that misfit are usually items where a misconception dominates the response,
which breaks the unidimensionality assumption of IRT. Rather than treating that as a defect, we
**use** it: the misfit list is exactly the set of items M3 finds most informative, and we show that
correspondence. Two models disagreeing in an interpretable way is a strong demo moment.

## M5 — Learning-Gain Predictor (LGP)

**Question it answers:** if I take action `a` in state `b`, how much weighted mastery do I gain?

This is the model that makes the agent *planful* rather than merely reactive.

**Family.** `XGBRegressor`, ~250 trees, depth 5, on `(state features, action features) → Delta WM`.

**Label construction.** From the pretraining cohort, for each `(state, action)` observed, the label is
the change in the *agent's own estimated* weighted mastery over the following 2 steps. Note carefully:
the label is the **estimated** delta, not the simulator's true delta. Using the true delta would be a
direct leak of ground truth into the agent ([`Contract.md`](./Contract.md) C4.7). We accept the
resulting bias and report it.

**Features (34):** the 24 M2 features, plus action type (one-hot, 9), target concept mastery and
variance, target concept prerequisite readiness, action cost, budget remaining fraction, interactions
remaining, max misconception posterior for the targeted misconception (for `EXPLAIN`), difficulty gap
`|b_i - theta|` (for `ASSESS`/`EASIER`/`HARDER`), steps since concept last seen (for `CONSOLIDATE`),
and engagement level.

**Output:** predicted `Delta WM`, one scalar per candidate action. Called batched — all 12 candidates
in one `predict` call.

**Metrics.**

| Metric | Target | Baseline |
|---|---|---|
| Spearman rank correlation with realised gain | ≥ 0.55 | Action-type mean 0.31 |
| RMSE | ≤ 0.045 | Constant predictor 0.071 |
| Top-1 accuracy (does argmax M5 match the truly best action?) | ≥ 0.42 | Random 0.11 |

Rank correlation matters more than RMSE here — the agent needs the *ordering* right, not the
magnitudes. We report both and say which one we optimised.

**Failure modes.** Systematically over-predicts gain for `TEACH` on unready learners, because in the
training data `TEACH` was usually issued when it was appropriate. The risk term's `r_waste` was added
specifically to counteract this — a nice example of two components covering each other's weaknesses,
and an honest story about how the design evolved.

## M6 — Action/Branch Ranker (ABR)

**Question it answers:** given this candidate set, which action would a good policy pick?

**Family.** Pairwise ranking (`XGBRanker` with `rank:pairwise`, fallback: a logistic pairwise model),
trained on candidate sets from the pretraining cohort. The relevance label for each candidate is its
realised 3-step forward gain, discretised into 4 grades.

**Why have this *and* M5?** They answer different questions. M5 predicts a *magnitude* for one action
in isolation; M6 learns *relative preference within a candidate set*, which is a different and easier
learning problem, and it sees set-level context (how many alternatives, their spread). In practice M6
is better at "never pick the obviously bad one" and M5 is better at "how much is this worth".

**Where it is used.** (1) Tie-breaking within 3% of the top utility. (2) The **disagreement
diagnostic**: when M6's top-ranked action differs from `argmax U`, we record it. Target disagreement
rate 10–25% — below 10% and M6 is redundant, above 25% and something is wrong with one of them. This
number goes on the Model Health panel.

**Metrics.**

| Metric | Target |
|---|---|
| NDCG@3 over candidate sets | ≥ 0.72 |
| Pairwise accuracy | ≥ 0.68 |
| Disagreement rate with `argmax U` | 10–25% (a health band, not a target to minimise) |

**Failure modes.** Trained on candidate sets produced by an earlier version of the policy, so it
inherits that policy's biases — classic off-policy bias. We mitigate by including B1 (random-policy)
rollouts in the training mix, which is cheap and materially widens the coverage.

## M7 — Engagement & Gaming Detector (EGD) · **BONUS**

**Question it answers:** is this learner still trying, or fatigued, or gaming the hint system?

**Family.** `RandomForestClassifier` over sliding-window sequence features → `{engaged, fatigued,
gaming}`, plus a continuous `fatigue` score from a logistic head.

**Features (12):** response-time z-scores over the last 5 (mean, slope, variance), hint requests per
item over the last 5, the fraction of hint requests that occurred before any answer attempt,
proportion of near-instant responses (< 1.5 s, indicating clicking without reading), accuracy trend,
step index, and whether hint level 3 was requested without an attempt.

**Label source.** The simulator's engagement dynamics produce ground-truth engagement states for the
pretraining cohort. Labels come from the simulator's *behavioural* output (the sequence of actions the
learner took), which the agent could observe in principle — not from its latent engagement parameter.

**Metrics.**

| Metric | Target |
|---|---|
| Macro-F1 (3 classes) | ≥ 0.68 |
| Gaming-class recall | ≥ 0.70 (missing a gamer is worse than a false alarm) |
| Lead time before accuracy collapse | ≥ 2 steps |

**Where it is used.** `r_waste` in the risk term, and trigger T5. Concretely: it stops the agent from
answering a bored learner's hint-spam with more hints, and pushes it toward `BRANCH` or `EASIER`.

**Failure mode.** The "Deliberator" profile (P2 — slow but accurate) looks like fatigue on
response-time features alone. Accuracy trend is the feature that separates them; we show the confusion
matrix so the residual error is visible.

**Cut position:** #5 on the cut line. If dropped, replaced by a response-time z-score threshold rule.

## M8 — Learner Archetype Classifier (LAC) · **BONUS**

**Question it answers:** once the pre-test is done, which kind of learner is this, so we can set
better priors?

**Family.** Gaussian Mixture Model (7 components, full covariance) fitted on pre-test feature vectors
from the pretraining cohort; at inference, the posterior over components supplies a *mixture* of
priors rather than a hard assignment.

**Features (9), computed from the 6 pre-test responses:** accuracy, mean response-time z-score,
response-time variance, hints used, whether the first error was on a low-depth concept, distractor
consistency (do errors point at one misconception?), and the mean difficulty of items attempted.

**Why the pre-test rather than the first few loop responses.** Every learner answers the *same* six
probe items in the same order, so the features are directly comparable across learners in a way
mid-loop responses — which depend on whatever the agent happened to choose — never are. It is also
more data. This was an open ambiguity in the first draft of the spec, resolved deliberately; see
`STATUS.md` → Resolved decisions RD-1.

**Output:** posterior over the 7 profiles in [`Simulation.md`](./Simulation.md) §3, used to set M1's
`p_init` and `lambda_forget` priors as a posterior-weighted blend.

**Metrics.**

| Metric | Target |
|---|---|
| Archetype classification accuracy after the pre-test | ≥ 0.55 (7-class; random 0.14) |
| Reduction in M1 MAE over the first 6 learning steps vs uniform prior | ≥ 15% |

The second metric is the one that matters — the archetype label is a means, not an end, and we report
it that way.

**Failure mode.** Six probe responses is still thin for a 7-class problem, and accuracy will be
mediocre. We say so. The posterior-blend design is what keeps a mediocre classifier useful, because a
confident wrong label would be worse than no label at all. That design choice is worth explaining if a
judge asks.

**Cut position:** #4 on the cut line. If dropped, M1 uses a uniform prior.

## Ablation plan

Each row removes one component (or its distinctive mechanism) and re-runs the headline experiment on
the evaluation cohort. Results table lives in [`Evaluation.md`](./Evaluation.md) §6 and renders on the
dashboard.

| Ablation | Replaced with | Hypothesis |
|---|---|---|
| M1 graph propagation off | Independent per-concept BKT | −4 to −7% headline |
| M2 removed | Fixed 0.5 prior for unseen concepts | −5 to −9%, mostly via bad `TEACH` gating |
| M3 removed | No `EXPLAIN` action, no T1 | −10 to −18% — expected to be the largest single loss |
| M4 removed | Authored difficulty priors only | −3 to −6% |
| M5 removed | Rollout only (`delta = 1`) | −6 to −12% and a 3x latency increase |
| M6 removed | Deterministic tie-break | −1 to −3% (small, and we will report it as small) |
| M7 removed | Threshold rule | −2 to −4%, concentrated in the P7 "Fader" profile |
| M8 removed | Uniform prior | −2 to −5%, concentrated in the first 6 steps |
| Rollout off (`delta = 0`) | = baseline B3 | −8 to −15% |
| Exploration off (`beta = 0`) | | −5 to −10%, worst on misconception-heavy profiles |
| Risk off (`gamma = 0`) | | Small mastery change, large frustration-metric increase |

**If an ablation shows a component contributes nothing, we report that honestly** and say what we
would do with more time ([`Contract.md`](./Contract.md) C2.3). A truthful negative result is worth
more to a judge than a suspiciously uniform table of wins.
